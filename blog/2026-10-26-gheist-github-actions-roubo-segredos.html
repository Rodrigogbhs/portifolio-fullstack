Hackers usam GitHub Actions para roubar segredos de repositórios privados

26 out 2026 · 09:54 (Brasília)Edição das 13:001 min de leitura

Campanha abusa de tokens roubados para expor credenciais nos logs de automação; Wiz recomenda revogar acessos e substituir segredos.

A Wiz revelou em 25 de outubro a campanha Gheist, que usa tokens roubados do GitHub para inserir automações maliciosas em repositórios. Os pesquisadores identificaram mais de 13.500 branches em mais de 850 contas comprometidas. A atividade é acompanhada desde 15 de setembro e continuava ativa em 24 de outubro; o número de organizações com segredos expostos não foi informado.

Segundo a Wiz, as automações registram segredos codificados nos logs do GitHub Actions. Os invasores baixam esses registros e apagam a execução em seguida. Houve exploração bem-sucedida em repositórios privados e no GitHub Enterprise. Nos repositórios públicos examinados, as execuções ficaram bloqueadas para aprovação. O GitHub confirma que essa proteção automática se aplica somente a repositórios públicos no github.com.

O risco alcança chaves de serviços em nuvem usadas por aplicações. A Wiz recomenda procurar branches com prefixo ci-sync-, revisar logs, revogar os tokens envolvidos e substituir todos os segredos acessíveis aos repositórios afetados. Apagar a branch não desfaz a exposição. Exigir aprovação para ambientes com credenciais de produção também é recomendado.
